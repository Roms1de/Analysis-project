# Анализ пользовательской воронки продаж

## Описание проекта

SQL-проект по анализу пользовательского пути и воронки продаж на основе данных о событиях пользователей.

**Цель исследования** — оценить конверсию пользователей на основных этапах воронки, определить проблемные этапы и выявить различия в поведении пользователей в зависимости от источника привлечения.

## Данные

Используется таблица `user_events` со следующими полями:

- `event_id` — идентификатор события;
- `user_id` — идентификатор пользователя;
- `event_type` — тип события;
- `event_date` — дата и время события;
- `product_id` — идентификатор товара;
- `amount` — сумма покупки;
- `traffic_source` — источник привлечения пользователя.

Основные этапы пользовательской воронки:

`Page View → Add to Cart → Checkout → Payment Info → Purchase`

## Проведенный анализ

С помощью SQL выполнены:

- расчет количества уникальных пользователей на каждом этапе воронки за последние 30 дней;
- расчет конверсии между последовательными этапами;
- анализ конверсии в покупку в зависимости от источника привлечения;
- расчет среднего времени прохождения основных этапов пользовательского пути;
- расчет ключевых финансовых метрик:
  - **AOV** — средняя стоимость заказа;
  - **ARPPU** — средняя выручка на платящего пользователя;
  - **ARPU** — средняя выручка на пользователя.

## Основные выводы

- Наиболее проблемным этапом воронки является переход от просмотра товара к добавлению в корзину — его конверсия составляет менее 31%. Это потенциальная точка роста, требующая дополнительного исследования поведения пользователей.
- Переход от ввода платежной информации к покупке имеет высокую конверсию — более 90%, поэтому данный этап не является основным источником потерь пользователей.
- Пользователи из социальных сетей обеспечивают большой объем трафика, однако конверсия в покупку составляет менее 10%.
- Email-канал привлекает меньше пользователей, но демонстрирует существенно более высокую конверсию в покупку — более 30%.
- Полученные финансовые показатели позволяют дополнительно оценивать эффективность привлечения пользователей, например, сопоставляя ARPU с CAC.
